# AXIOM_003 — One Loop First

> A system is only allowed to grow after one complete gameplay loop
> has been implemented, validated and proven fun.
>
> Never build breadth before depth.

version: "1.0.0"
status: Accepted — Architecture Freeze Compatible

---

## Principle

Project Celestial grows by completing one perfect loop.
Not by accumulating features.

## Core Gameplay Loop

```
Cultivate → Improve → Breakthrough → Explore → Acquire Resources → Cultivate Again
```

Everything must strengthen this loop.

## Rules

### Rule 1
Never build features that do not improve the current gameplay loop.

### Rule 2
If a feature cannot be experienced by the player inside one gameplay loop,
it should not be implemented yet.

### Rule 3
Depth always precedes breadth.
Better: One polished system. Than: Twenty unfinished systems.

### Rule 4
Every feature must answer: Which part of the gameplay loop does this improve?
If no answer exists, the feature must be postponed.

### Rule 5
Do not implement content merely because it exists in the world bible.
Lore does not determine priority. Gameplay does.

### Rule 6
Complexity is earned.
New mechanics are introduced only after the previous loop has been validated.

## Hermes Decision Rule

```
Does this improve the current loop?
  YES → Implement
  NO  → Reject or postpone
```

## Success Metric

The player voluntarily repeats the gameplay loop.
If players stop repeating the loop, adding more features is forbidden.
Instead, improve the loop itself.

## Alchemy / Pets / Guild Wars / Flying Swords

All postponed until the core loop is proven fun.
