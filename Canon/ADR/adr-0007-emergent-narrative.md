# ADR-0007: Emergent Narrative — 涌现式叙事

Date:       2026-07-23
Status:     Proposed
Author:     Architect

---

## Context

narrative_schema.yaml 定义了 Scene Template——如何将单个场景的模拟结果转为叙事文本。但这是"微观"叙事。

用户要求的是"宏观"叙事：灵脉枯竭 → 宗门资源不足 → 弟子外出 → 遭遇妖兽 → 获得古遗迹地图 → 势力争夺 → 玩家卷入。这是一条因果链，而不是一个场景。

关键问题：模拟产生了离散事件。如何把这些离散事件串成一个"故事"？

## Decision

**叙事即因果链。**

不预写故事。故事是因果链的可视化。

### 核心流程

```
Simulation Tick → Events → Causal Chain Detection → Arc Formation → Narrative Output
```

### 因果链检测

当事件 A 的资源/状态变化直接导致了事件 B 时，创建 LED_TO 边（KG 已有此边类型）。

检测规则：
- 资源因果：A 导致资源变化 → B 是对该资源变化的响应
- 位置因果：A 导致 NPC 移动到新位置 → B 在新位置发生
- 关系因果：A 改变了人际关系 → B 是由该关系驱动的行为
- 信息因果：A 的信息被 B 获知 → B 是对该信息的反应

### 叙事弧（Arc）

一条因果链 + 长度 ≥ 3 + 重要性总和 ≥ 15 → 自动提升为叙事弧。

弧有起点和终点：
- 起点：链中第一个事件（根因）
- 终点：链中最后一个事件（当前状态）
- 中段：因果传递路径

### 多视角编织

一个因果链涉及多个 NPC。每个 NPC 对该链有不同的视角：
- 全知视角：展示完整因果链（用于世界观叙事）
- NPC 视角：只展示该 NPC 参与的事件（用于角色叙事）
- 玩家视角：只展示玩家可以感知的事件（用于玩家体验）

### 玩家进入点

玩家不是被"塞进"一个预先写好的故事。
玩家的 KG 边与因果链相交时，玩家自然进入叙事。

```
因果链：灵脉枯竭 → 宗门危机 → 弟子外寻 → 妖兽袭击 → 获得地图

玩家进入方式：
- 如果在宗门 → 从"宗门危机"进入
- 如果在野外 → 从"弟子外寻"阶段相遇
- 如果拥有古遗迹相关信息 → 从"获得地图"进入
```

## Design

```
narrative_engine/
├── causal_chain_detector  ← 因果链检测规则（新）
├── arc_composer           ← 弧组合规则（新）  
├── scene_composer         ← 场景模板填充（已有）
└── perspective_weaver     ← 多视角编织规则（新）
```

## Alternatives

| 方案 | 优点 | 缺点 | 结果 |
|------|------|------|------|
| 预写剧情树 | 可控 | 不涌现、不自由 | Rejected |
| LLM 串联事件 | 灵活 | 不一致、不可复现 | Rejected |
| 因果链自动检测 | 涌现、可复现 | 需要定义检测规则 | Accepted |

## Consequences

- 同一个模拟结果，不同视角产生不同叙事
- 叙事弧是动态的——新事件可以延长弧或分叉出新弧
- 玩家不是"主角"，玩家是进入因果链的"变量"
- KG 的 LED_TO 边从"可选"变为"叙事核心基础设施"
